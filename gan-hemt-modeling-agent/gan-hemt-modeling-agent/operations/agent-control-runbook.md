# Agent 性能与恢复运行手册

## 1. 目的

本手册用于测试日监控并处置四类问题：端到端耗时超预算、进程/会话崩溃、竞赛任务无法完成、某一建模环节连续失败。具体机制与指标见 [Agent 效率、恢复、完成率与失败控制](../docs/08-agent-efficiency-reliability.md)。

当前项目尚无可执行入口，本文件先定义操作顺序；实现后所有命令必须由真实 CLI 帮助和干净环境演练校验。

## 2. 启动前检查

正式窗口前必须用发布候选执行一次可阻断的 dry-run；官方计时开始后仍要重新执行轻量 preflight。后者的鉴权、网络和修复等待全部计入 24 小时墙钟，只是不消耗尚未发起的拟合调用预算。

- 时钟、磁盘、网络、MCP endpoint、国产 LLM endpoint 可用。
- 两个器件的运行目录、状态存储和锁空间独立。
- 最新发布候选的代码、依赖、配置、Schema 和提示词摘要一致。
- 检查点存储可写，原子写入与读取自检通过。
- 操作账本无遗留 `IN_FLIGHT/OUTCOME_UNKNOWN`；若存在，先对账。
- 性能、恢复、完成判定和失败分类策略已加载。
- 每器件 MCP 合规账本和整组国产 LLM 合规检查已启用；每器件 LLM 调用若作为项目加严目标需单独标识。

## 3. 运行中观察顺序

每个时间门禁先检查：

1. 两器件是否都仍有可提交保底卡。
2. `SUBMISSION_HARD` / `STRICT_QUALITY_REQUIRED` 完成度和 `pair_verdict` 候选缺口。
3. 剩余时间与 critical path 预测；只有版本/fixture 匹配且预登记历史样本 `n≥20` 时使用 P95，否则使用历史 max、保守上界和当前 deadline slack。
4. 是否存在 `OUTCOME_UNKNOWN`、重复动作或未分类失败。
5. 当前较弱器件及继续优化的预期收益。

只有上述状态安全后才继续可选 retune。

## 4. 耗时超预算

按以下顺序减载：

1. 停止没有最小收益的 retune 和重复诊断。
2. 取消尚未开始的可选高场/场板或联合精修任务。
3. 若官方允许，切换到已演练的双器件安全并行或批量只读调用。
4. 限制 LLM 输出并改用确定性计划/停止规则；不得跳过国产 LLM 合规证据。
5. 转入最终 QA、Schema、冻结和提交包生成。

禁止临时开启未经回归的缓存、投机拟合、多 Worker 或新模型。

## 5. 崩溃与恢复

1. 按 `run_id + scope_id` 获取单一恢复所有权：器件拟合使用 `device:<id>`，全局总结、打包、冻结、上传和回执对账使用 `global`。
2. 读取最近完整检查点和操作账本水位。
3. 对 `IN_FLIGHT/OUTCOME_UNKNOWN` 远端操作查询状态；不能确认时不得盲重试。
4. 校验最佳模型卡、候选卡和事件摘要。
5. 从最近完整节点续跑，不从头重新建模。
6. 恢复后先执行一个只读健康检查和状态一致性检查，再允许副作用操作。
7. 记录崩溃点、恢复点、耗时、是否重复副作用和最终结果。

检查点损坏时回退到上一个完整检查点。所有检查点均不可用时先令 `execution_status=FAILED_SAFE` 并保留最后一个可独立验证的模型卡与证据；随后由确定性校验器给出 `DEVICE_DEGRADED_DELIVERABLE / DEVICE_FAILED_SAFE / DEVICE_FAILED`，不能把执行状态直接当作完成结果。

## 6. 环节连续失败

- 逻辑/Schema/参数错误：不做相同重试，修正输入或切换已登记动作。
- 网络/限流/5xx：按预算退避；连续失败触发熔断并切换另一器件。
- 拟合不收敛：缩小参数组、回滚或跳过可选分支。
- QA 退化：确定性拒绝候选，禁止 LLM 强行接受。
- LLM 非法输出：有限自愈、备用国产模型或确定性降级。
- 未知远端结果：进入对账流程，不创建重复拟合任务。
- 提交产物失败：从冻结卡和不可变日志重建，不修改核心算法。

## 7. 完成判定与提前停止

提前停止前逐器件确认模型卡、最终 QA、Schema/可加载性、日志连续性和每器件 MCP 合规证据；随后在整组层确认国产 LLM 有意义决策证据、2 卡、2 日志、1 总结及摘要一致。

真正不适用的阶段可以标记 `NOT_APPLICABLE`；`SUBMISSION_HARD` 失败使包无效，`STRICT_QUALITY_REQUIRED` 失败最多形成 `DEVICE_DEGRADED_DELIVERABLE`，`OPTIONAL` 跳过不影响等级。只有两器件均为 `DEVICE_COMPLETE` 才是 `STRICT_COMPLETE`；降级有效包记为 `VALID_DEGRADED_PACKAGE`，缺少硬门禁记为 `INVALID_PACKAGE`。上传/回执另以 `submission_status` 记录，只有截止前 `CONFIRMED` 才算交付。

## 8. 赛后复盘

- 汇总每次原始耗时、max 和 critical path；同版本样本 `n≥20` 时才按预先固定算法报告 P50/P95。
- 分别计算严格包率、有效包率、截止前交付率、恢复安全不变量、续跑成功、安全遏制、六类失败率、重复副作用和未分类失败。
- 选取影响完成率或耗时最大的 1～3 个原因。
- 将对应运行目录、失败信封和恢复轨迹加入回归用例。
- 每次只调整一个主要策略，完整回归后再接受。
