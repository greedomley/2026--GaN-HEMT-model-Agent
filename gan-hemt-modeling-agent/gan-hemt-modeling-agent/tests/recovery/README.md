# 崩溃恢复测试规划

必须在以下位置注入进程终止或网络故障：

- 副作用操作意图写入前后。
- MCP 已执行但本地未保存结果时。
- QA 完成、候选接受/回滚和保底卡形成后。
- 两器件调度切换和最终产物冻结时。

每个用例断言：

- 从最近完整检查点续跑而非从头重跑。
- `OUTCOME_UNKNOWN` 先查询对账，不重复副作用。
- 最佳已验证卡不丢失、不被候选覆盖。
- 两器件状态、日志和产物无交叉。
- 恢复入口重复调用仍只有一个恢复执行者。
- 最终状态和无崩溃基线在定义容差内一致。

恢复所有权按 `run_id + scope_id` 测试：除 `device:<id>` 外，还要覆盖全局总结、打包、冻结、上传和回执对账的 `global` 单写者。

恢复指标必须分开：安全不变量（零重复副作用、零最佳卡丢失、零作用域串扰）、在 deadline 内达到无故障等价结果的续跑成功，以及无法对账时的安全遏制。`FAILED_SAFE` 不计续跑成功。

项目初始发布目标是：本文件列出的必测可恢复点安全不变量与续跑成功均为 100%；预先冻结故障模型/注入点且不少于 20 次随机注入时续跑成功率不低于 95%；所有注入的安全不变量通过率仍为 100%。
