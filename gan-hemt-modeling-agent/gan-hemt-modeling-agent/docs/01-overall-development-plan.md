# 总体开发计划

## 1. 总体策略

项目采用“先确定性基线、后 Agent 自动化”的建设顺序。只有当固定流程能够通过 MCP 生成一份可仿真、可 QA、可复现的模型卡后，才开始让 Agent 自主选择提参顺序和 retune 策略。

核心路径如下：

> 官方契约确认 → MCP 最小链路 → 人工可控建模基线 → 确定性提参引擎 → Agent 状态机 → 合成数据回归 → 性能/恢复/失败闭环 → 交付冻结 → 24 小时正式运行

## 2. 阶段划分

### P0：官方契约与问题闭环

主要工作：

- 获取赛题 Q&A、官方模型卡 Schema、MCP 工具定义和 QA Checklist。
- 确认认证、限流、超时、并发、会话寿命和重连规则。
- 确认异步任务、幂等键、状态查询/结果重取/取消及“远端已执行但响应丢失”的对账语义。
- 确认两器件能否并行、允许的 LLM 范围及日志审计口径。
- 建立“已确认事实、暂定假设、阻塞问题”三类清单。

阶段产物：契约清单、问题清单、接口边界说明。

通过门槛：关键 Schema、MCP 能力和测试日提交方式不存在未标记的猜测。

### P1：工程基线

主要工作：

- 固定 Python、Agent 框架和国产大模型选型。
- 确定配置、密钥、日志、状态存储和产物目录规范。
- 建立统一的运行标识、器件标识、会话标识和时间戳规范。
- 定义阶段结果、操作账本、原子检查点、完成结果、失败信封和性能事件的内部契约。

阶段产物：工程约定、运行环境说明、目录与命名规范。

通过门槛：在干净环境中能够完成启动前检查，且密钥不进入仓库和日志。

### P2：MCP 最小闭环

主要工作：

- 完成认证、健康检查和会话生命周期管理。
- 验证数据概览、模型选择、参数读写、拟合、QA、可视化和模型卡导出能力。
- 保存每次调用的操作意图、请求/返回摘要、分段耗时、错误分类、重试/对账结果和关联检查点。

阶段产物：MCP 能力矩阵、契约测试集、最小端到端调用记录。

通过门槛：能够从创建会话走到导出模型卡；失败可分类、可判断重试资格并可审计，副作用结果未知时能够先对账且不会重复执行。

### P3：非 Agent 建模基线

主要工作：

- 先用固定流程完成一套 ASM-HEMT 参数提取。
- 建立参数分组、冻结/解冻、物理上下界和接受/回滚规则。
- 建立每轮拟合前后误差、QA 和参数变化对比。
- 为每个阶段定义前置/后置条件、适用性、deadline、失败分类和 fallback。

阶段产物：首份基线模型卡、提参顺序、参数策略和复现报告。

通过门槛：相同输入和配置可稳定复现，模型卡可被仿真器加载并通过基础 QA。

### P4：确定性领域引擎

主要工作：

- 将数据审计、参数策略、拟合评估、QA、评分代理、回滚和停止条件模块化。
- 将所有物理硬约束放入领域策略，不交给 LLM 自由生成。
- 建立模型卡版本链、操作意图账本、原子检查点、恢复互斥和未知结果对账机制。
- 建立单器件四级、双器件三级包结果和独立 `submission_status`，分别统计严格包率、有效包率与截止前交付率。

阶段产物：确定性建模用例定义、状态模型、领域规则清单。

通过门槛：任意参数更新都经过边界校验；结果退化时能回滚；运行可断点恢复。

### P5：Agent 状态机

主要工作：

- 使用 LangGraph 表达节点、边、条件路由、重试和状态持久化。
- 接入国产大模型，用于提参计划、异常诊断、retune 建议和总结。
- 为每次决策保留输入事实、可选动作、选择结果、依据和执行结果。
- 确定性节点不调用 LLM；结构/参数错误只做有限自愈，相同动作无新证据重复时熔断或换已登记策略。

阶段产物：可审阅的决策图、状态定义、决策记录和异常路径。

通过门槛：Agent 能以受控轮次自主完成全流程，不存在绕过参数边界、QA、恢复对账、完成判定或产物校验的路径。

### P6：合成数据与回归体系

主要工作：

- 基于 SPICE + ASM-HEMT 构造差异化器件族。
- 覆盖阈值、导通能力、寄生、自热、陷阱、kink、温度和噪声变化。
- 设置开发集、回归集和严格隔离的模拟隐藏集。
- 加入缺测、异常点、服务错误、远端执行结果未知、检查点损坏、重复恢复和中断恢复场景。

阶段产物：数据清单、回归基线、困难样例库。

通过门槛：每次变更都能在预登记 manifest 上比较 QA、RMSE、调用量、关键路径原始值/max（同版本 `n≥20` 时再算 P50/P95）、严格包率、有效交付率、分环节失败、恢复结果和最差器件表现。

### P7：评分与鲁棒性优化

主要工作：

- 先消除模型卡非法和物理 QA 失败，再降低曲线误差。
- 根据总分中的最差器件项，优先改善较弱器件。
- 优化时间预算、调用预算、参数组顺序和停止策略。
- 验证国产大模型切换和 MCP 故障降级。
- 先冻结顺序基线，再逐项验证低轮次、安全只读并行、精确结果重放和连接复用；速度优化不得降低完成率、QA、最差器件或恢复成功率。
- 将每个正式演练失败归入稳定错误码并沉淀为回归用例，优先闭环影响完成率或关键路径最大的 Top 1～3 原因。

阶段产物：评分看板、双器件调度策略、关键路径报告、完成漏斗、失败 Top-N 和容错报告。

通过门槛：多次盲测中两套器件均稳定达到目标，无依赖单次随机结果的“幸运运行”。

### P8：交付冻结与竞赛演练

主要工作：

- 冻结主分支、依赖、配置模板、入口和官方 Schema 校验。
- 演练完整 24 小时流程和提前终止流程。
- 演练远端已执行但本地未记账、最新检查点损坏、并发恢复争抢和再次崩溃。
- 验证 2 份模型卡、2 份日志、1 份总结的命名、内容和可读性。
- 验证每个器件 MCP 有效调用次数与整组国产大模型有意义决策记录；每器件 LLM 仅在被设为项目加严目标时单独验收。

阶段产物：候选发布版本、演练报告、提交清单和故障手册。

通过门槛：干净机器一键启动；本文列出的必测点恢复安全不变量为 100%，续跑成功与安全遏制分开报告；严格包、降级包和提交状态分开；所有官方产物自动校验通过。

### P9：正式测试日

按 [24 小时竞赛运行计划](06-competition-runbook.md) 执行。正式运行期间不再引入未经回归验证的新算法，只允许配置级调整和预先演练过的恢复操作。

## 3. 质量门禁

每个阶段必须同时满足以下维度：

| 维度 | 最低要求 |
|---|---|
| 正确性 | 模型卡可加载、Schema 合法、输出完整 |
| 物理性 | 参数范围、单调性、对称性、kink 等 QA 有明确结论 |
| 精度 | 在自建隐藏网格上记录归一化 RMSE |
| 鲁棒性 | 双器件、异常数据、重试和恢复场景均有回归结果 |
| 可审计性 | MCP、LLM、决策、参数版本和 QA 全链路关联 |
| 可复现性 | 固定配置和数据版本能够复现实验结果 |
| 预算 | 时间、MCP 调用、LLM Token 和重试次数受控 |
| 效率 | 节点/LLM/MCP/等待/检查点耗时可重算，关键路径与阶段 deadline 可验证 |
| 恢复性 | 未知副作用先对账，检查点可回退，重复副作用与最佳卡丢失均为 0 |
| 完成性 | 严格完成、降级可提交和失败安全由确定性判定器区分 |
| 失败控制 | 所有终态失败可分类、可归因、受重试预算约束并进入回归库 |

## 4. 开发优先级

1. 模型卡合法且可仿真。
2. 物理 QA 达标。
3. 两套器件都达到稳定基线。
4. 保证严格包率、截止前有效交付率和崩溃恢复门禁。
5. 降低隐藏网格上的曲线误差和最差器件风险。
6. 在不降质条件下优化端到端速度与调用成本。
7. 完善展示和运行总结。

## 5. 总体完成定义

项目完成不是“Agent 能运行”，而是能够在未知器件和受限时间下稳定生成两份有效模型卡，并提供可复现、可恢复、可审计的全部证据链；严格完成、降级可提交和失败安全不得混为同一成功口径。四项横切能力的详细定义见 [Agent 效率、恢复、完成率与失败控制](08-agent-efficiency-reliability.md)。
