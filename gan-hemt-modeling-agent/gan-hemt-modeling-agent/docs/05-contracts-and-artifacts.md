# 契约与交付物规划

## 1. 契约优先

本项目不在取得官方材料前虚构 Schema。`contracts` 下的子目录仅定义契约归属位置，后续必须保存官方版本、版本号、来源和确认日期。

## 2. 契约目录

| 目录 | 计划内容 |
|---|---|
| `contracts/mcp` | MCP 工具清单、请求/响应、错误、会话和限流契约 |
| `contracts/model_card` | 官方 ASM-HEMT 模型卡 Schema 和校验要求 |
| `contracts/run_log` | MCP、LLM、决策、参数、QA 和时间统计日志契约 |
| `contracts/run_summary` | 单次竞赛运行总结格式 |
| `contracts/decision_record` | Agent 每次决策的结构化记录格式 |

## 3. 正式交付物

测试日结束前必须形成：

- 器件 1 模型卡。
- 器件 2 模型卡。
- 器件 1 运行日志。
- 器件 2 运行日志。
- 一份全局运行总结。

测试日开始前必须具备：

- 完整代码仓库。
- Agent 图和状态定义。
- Agent 主入口。
- 依赖声明。
- 架构图。

当前骨架只覆盖上述内容的目录和设计位置，不生成正式文件模板。

## 4. 运行日志最小证据链

日志需要能够回答：

1. 哪个器件、哪次运行、哪个 MCP 会话。
2. 在什么状态下调用了什么工具。
3. 调用目标、耗时、结果和错误是什么。
4. 使用了哪个国产大模型，调用次数和 Token 统计是多少。
5. Agent 看到了哪些事实、有哪些允许动作、为何选择当前动作。
6. 参数卡从哪个版本变为哪个版本。
7. RMSE 代理和 QA 如何变化。
8. 为什么接受、retune、回滚或停止。

认证 Token、API Key 和其他密钥不得写入日志。

## 5. 冻结与校验

提交前校验顺序：

1. 文件存在且器件映射正确。
2. 模型卡符合官方 Schema。
3. 模型卡可由指定仿真链加载。
4. 日志满足官方字段和反作弊审计要求。
5. 每个器件有效 MCP 调用不少于规则要求。
6. 指定国产大模型 API 调用证据存在。
7. 日志、总结和模型卡版本号相互一致。
8. 无密钥、临时文件或正式测试原始数据泄露。
9. 计算摘要或校验值，随后冻结，不再覆盖。
