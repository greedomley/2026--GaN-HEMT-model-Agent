# 模块职责清单

本文中的 `src/<logical_layer>` 是逻辑职责路径。第一批代码落盘时必须在扁平 `src/` 与单一命名空间 `src/gan_hemt_modeling_agent/` 中二选一，并一次性同步全部文档；当前骨架不创建两套重复模块。

## 1. `src/entrypoints`

系统主入口边界。负责读取运行配置、执行 preflight、启动正式运行和返回退出状态；不包含建模规则。

## 2. `src/orchestration`

| 子模块 | 职责 |
|---|---|
| `graph` | Agent 决策图、节点和边的结构定义 |
| `state` | 图状态、节点输入输出和状态演进 |
| `routing` | 条件分支、阶段 deadline、动作循环检测、熔断、恢复和安全降级路由 |
| `checkpoints` | 原子检查点、状态 Schema 迁移、完整性校验、操作账本水位和恢复点选择 |

## 3. `src/agents`

| 子模块 | 职责 |
|---|---|
| `planner` | 基于数据可用性、器件特征和预算形成提参计划 |
| `data_analyst` | 解释数据审计结果并标记风险，不直接修改原始数据 |
| `extraction_strategist` | 在允许策略集合内选择参数组、目标和下一轮动作 |
| `qa_reviewer` | 解释 QA 失败及误差分布，提出受约束的 retune 建议 |
| `recovery_supervisor` | 根据结构化失败从已登记策略中选择恢复路径；不自行发明重试，也不承担幂等与对账正确性 |
| `reporter` | 生成决策摘要、运行总结草稿和人工可读解释 |

这些是职责角色，不要求一定实现成相互聊天的多个进程或多个模型。

## 4. `src/application`

| 子模块 | 职责 |
|---|---|
| `bootstrap` | 启动检查、认证检查、运行上下文初始化 |
| `run_management` | 单次正式运行生命周期、阶段契约、进度账本、deadline 传播和最终结果管理 |
| `device_coordination` | 两器件独立运行、关键路径、跨器件预算调度和官方许可下的安全并行 |
| `data_audit` | 数据类型、偏置、温度、单位、覆盖范围和异常检查用例 |
| `extraction` | 分组参数提取用例编排 |
| `retune` | QA/误差驱动的受约束再调优用例 |
| `validation` | 模型卡可加载性、物理 QA、误差代理和稳定性验证 |
| `submission` | 竞赛产物冻结、校验和提交包准备 |
| `recovery` | 调用 MCP/持久化端口编排未知远端结果对账、检查点续跑、业务回滚和失败安全用例 |

## 5. `src/domain`

| 子模块 | 职责 |
|---|---|
| `device` | 器件标识、几何/温度/偏置上下文和器件状态 |
| `dataset` | 服务端数据引用、数据能力清单和质量结论 |
| `run` | 运行阶段、阶段适用性、预算、deadline、状态和终止原因 |
| `decision` | 决策事实、候选动作、选择、依据和结果 |
| `parameter_groups` | ASM-HEMT 参数组、依赖、冻结/解冻和顺序策略 |
| `fitting` | 拟合目标、候选结果、误差比较、接受和回滚规则 |
| `qa` | 物理 QA 项、严重等级、通过规则和修复映射 |
| `scoring` | QA 与曲线误差代理、双器件鲁棒性指标 |
| `model_card` | 模型卡版本、完整性、来源和检查点关联 |
| `policies` | 参数范围、迭代、停止、降级和安全硬规则 |
| `failure` | 稳定失败分类、错误信封、可重试性、副作用状态和处置资格 |
| `outcome` | 单器件四级、双器件三级包结果，以及独立平台提交状态与统计口径 |

## 6. `src/ports`

| 子模块 | 职责 |
|---|---|
| `modeling_mcp` | MeQLab 能力的供应商无关端口，包含幂等键、异步任务状态、结果查询/取消和能力声明 |
| `llm` | 国产大模型推理、结构化输出和统计端口 |
| `persistence` | 图状态、原子检查点、操作账本、恢复锁、模型卡版本和运行元数据端口 |
| `telemetry` | 结构化事件、阶段耗时、关键路径、完成漏斗、恢复和失败指标端口 |

## 7. `src/adapters`

| 子模块 | 职责 |
|---|---|
| `primarius_mcp` | 认证、会话、连接复用、MCP 工具调用/状态查询、错误归一化和结果映射；只读缓存仅在官方允许且实测有收益后加入 |
| `domestic_llm` | DeepSeek/Qwen/GLM/Kimi/MiniMax 等可替换接入边界 |

## 8. `src/infrastructure`

| 子模块 | 职责 |
|---|---|
| `persistence` | 状态和检查点的具体存储实现位置 |
| `observability` | UTC/同进程单调计时、JSONL 事件、阶段/调用 span、依赖图、关键路径、完成漏斗、恢复/失败聚合和性能报告的唯一指标真源 |
| `resilience` | 操作意图账本、分类超时/重试/退避/熔断、幂等与恢复锁等技术原语；不决定继续拟合、回滚或降级 |
| `runtime` | 环境变量、密钥注入、时钟和运行环境信息 |

## 9. `src/governance`

| 子模块 | 职责 |
|---|---|
| `compliance` | 国产大模型调用、每器件有效 MCP 调用等竞赛规则检查 |
| `budget` | 运行/器件/阶段层级 deadline，MCP 调用、LLM Token、检查点和重试预算 |
| `artifact_validation` | 模型卡、日志、总结的 Schema 和完整性校验 |
| `completion` | 确定性判定器、单/双器件包结果、保底卡、提交就绪和截止前交付门禁 |
| `reliability` | 失败预算、未分类错误、性能不降质和恢复演练发布门禁 |

## 10. 仓库支撑目录

| 目录 | 职责 |
|---|---|
| `contracts` | 保存官方接口/产物契约，并在 `runtime_control/` 隔离内部阶段、操作、检查点、完成、失败和性能 Schema |
| `config` | 环境、模型、提参、QA、预算及 `policies/` 中性能/恢复/完成/失败策略的无密钥配置位置 |
| `data` | 自建合成、回归、夹具和清单；不保存正式测试原始数据 |
| `artifacts` | 每次运行产生的模型卡、日志、总结、QA、决策轨迹及 `quality/` 指标报告 |
| `tests` | 单元、契约、集成、端到端、性能、恢复、完成率、失败控制、回归和竞赛演练 |
| `operations` | 本地/竞赛运行、性能减载、崩溃恢复、失败处置和完成判定手册 |

四项 Agent 横切能力的具体状态、指标、失败矩阵和测试口径见 [Agent 效率、恢复、完成率与失败控制](08-agent-efficiency-reliability.md)。
